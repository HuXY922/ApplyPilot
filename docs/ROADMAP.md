# ApplyPilot delivery plan

## Target and acceptance
36 hours for P0, up to 72 hours for P1. Time is a planning budget, not evidence of completion. The application must run independently of its development assistant. Preserve Career Desk's Python API and SQLite state machine; no vector database, RAG service or multi-agent infrastructure is required.

## P0 (0–36 hours)
1. 0–4 h: inspect and reproduce baseline; sanitize fixtures; establish feature matrix and test categories.
2. 4–12 h: versioned reviewed profiles, scoped data, observation history, idempotent events, public-demo session isolation.
3. 12–22 h: bounded real discovery, official verification, normalization, deterministic pass/fail/unknown gates, evidence-linked analysis.
4. 22–30 h: grounded resume revisions and full persistent UI flow.
5. 30–36 h: network/E2E/security checks, clean-install verification, source/license review and release. External billing, repository access and model credentials remain explicit release dependencies.

## P1 (36–72 hours)
- Controlled, owned form adapter: fill, read back, pause, cancel, consent bound to exact content, verifiable receipt.
- Human handoff for login and OTP; never store credentials or bypass challenges.
- Durable execution logs and recovery. An unknown submission cannot be automatically retried.
- Optional authorized read-only scheduled search. No unattended applications.

## P2
Additional employer adapters, richer parsing, complete international policy configuration, advanced analysis, and production multi-user accounts. Do not imply these are already supported.

## Critical release gates
- No real applicant data, cookies, working keys or production database published.
- No cross-session record access, unrestricted remote fetch, or unbounded model spend.
- Only official-source evidence can yield verified_job; announcement/lead/demo remain distinct.
- Rediscovery cannot reset a skipped/applied decision. Availability and application progress are independent.
- Profile extraction is an unreviewed draft. Resume suggestions cannot invent facts or metrics.
- Manual submitted status is explicitly user-attested; external automated success requires a receipt. Timeouts stay unknown.
- Rules-only, mock, recorded evidence, real network and live model output are visibly distinguished.

## Risk order
1. Data exposure, misleading submission success, or duplicate submissions.
2. Verification bypass, wrong eligibility, lost decisions or failed migrations.
3. Source access/schema changes and coverage gaps in Chinese campus recruiting.
4. Missing model credentials, GitHub access, billing approval or durable hosting.
5. Browser adapter breadth and advanced UI polish.
