# 招聘方体验路线（约 5 分钟）

使用虚构身份“林小禾”，不要输入真实手机号、简历或密钥。

1. **总览**：确认“虚构演示”与模型模式标记。未配置模型时是规则模式，不能当作真实 LLM 演示。
2. **个人档案**：查看教育、经历、技能与城市偏好，修改一项虚构资料，审核并保存。也可导入包含虚构经历的 TXT/PDF/DOCX，观察它先成为草稿，需要人工确认。
3. **岗位雷达**：选择校招，搜索“评测”，城市选上海/深圳。只有网络成功核验的真实岗位才显示官方来源与核验时间；示例岗位始终标注虚构。来源是有限图谱，可能部分失败或没有结果。
4. **匹配分析**：打开岗位，查看学历/届别/城市等检查、经历证据和资格待确认项。模型不能把 unknown 自动改成满足。
5. **简历工作台**：查看原文、建议、理由、证据引用；当前保守建议以已有段落排序和重点前置为主。修改档案后，旧输出应标为过期。
6. **投递追踪**：收藏或跳过岗位，刷新页面，检查状态与历史仍存在。“已提交”需要明确的用户陈述，页面会标明是手动记录。未知结果不能自动重试。
7. **受控填写演示**：进入“模拟表单”。填写虚构字段，readback 后准备确认；修改字段应使旧确认失效。确认后仅产生本应用的 simulation 回执，不影响真实岗位状态。

## 演示数据

- `candidate-profile.json` / `radar-batch.json`：独立编写的虚构旧接口测试资料。
- `applypilot_core/store.py`：新 UI 的虚构档案和三个示例岗位。
- 真实岗位只来自显式网络运行；不将预置数据冒充实时搜索。

## 成本和安全

访客不填写模型 Key，Key 由项目所有者在服务器配置。调用受预算限制，失败也记账。会话默认24小时过期，公共演示不适合保存真实求职资料。产品不会登录招聘网站、绕过验证码或提交真实申请。

## 评审时区分四种证据

- Mock/单元：规则、边界和错误处理。
- 真实网络：官方源返回、身份和有效性核验。
- HTTP 集成：浏览器以外的真实本机 HTTP + SQLite 流程。
- 浏览器 E2E/人工验收：实际点击、布局、上传、取消、刷新及返回流程。

当前未验证的部分必须保留未通过标记。详情见 TEST_REPORT.md。
